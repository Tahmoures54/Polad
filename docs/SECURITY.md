# امنیت پولاد

## اصول

- حداقل دسترسی: عضو فقط تراکنش خودش را می‌خواند؛ مدیر صندوق خودش را.
- نوشتن مالی (تأیید، وام، قرعه، صورتحساب) فقط با Admin SDK در Cloud Functions.
- کلاینت هرگز `client_secret` بانکیما را نمی‌بیند.
- پشتیبان‌گیری خاموش (`allowBackup=false`) روی Android.
- Storage فیش: حداکثر ۵MB و فقط image، مسیر `{uid}/...`.
- قوانین Firestore با `funds/{id}/members/{uid}.role` — نه `request.auth.token.admin` سراسری، چون چندصندوقی را می‌شکند.

## OTP

تولید: Firebase Phone Auth. حالت دمو کد ثابت `123456` دارد و نباید در بیلد فروشگاه فعال باشد (`POLAD_DEMO=false`).

## پیامک بانکی

فقط Android و فقط با رضایت صریح مدیر. iOS API عمومی برای خواندن اینباکس ندارد. Play Policy: دلیل استفاده را در Data safety «تطبیق واریز صندوق» اعلام کنید.

## تهدیدات پوشش‌داده‌شده

| تهدید | کنترل |
| --- | --- |
| عضو موجودی را دستکاری کند | موجودی فقط در Functions |
| مدیر صندوق دیگر | عضویت per-fund |
| کارمزد پنهان از عضو | صورتحساب جدا + متن قانونی در UI |
| فیش جعلی | تأیید دستی مدیر + تطبیق SMS/بانکیما |
